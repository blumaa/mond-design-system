# Working inside a design system

A design system's promise is that a rebrand is one file and nothing else moves.
Every rule here exists because some ordinary-looking line of code quietly breaks
that promise: a literal hex that survives the rebrand, a hard-coded 12px the
scale can no longer move, a component that pins itself to the bottom of a screen
it does not own.

The rules are in `RULES.md` beside this file, generated by
`dsbridge rules --markdown`. Read it before writing CSS in an unfamiliar repo.

## What to run

| you want | run |
| --- | --- |
| what this repo violates today | `dsbridge check` |
| what a token is called | `dsbridge tokens --grep <text>` |
| why a rule exists | `dsbridge rules <id>` |
| what an app would have to move to adopt the system | `dsbridge migrate` |

Configuration lives in `dsbridge.config.json` at the repo root: the token
prefix, where the design system's stylesheet lives, the component taxonomy, and
any exemptions. There is no global install to worry about — the repo that owns
the design system owns the rules.

## The two kinds of rule

**Checked.** `dsbridge check` proves them, so a violation is a fact. Fix it, or
exempt it in the config with the reason written beside the code. Never fix one
by making it unmeasurable — moving a literal into a JavaScript string satisfies
no rule and defeats every one of them.

**Judgement.** No tool can prove them. Whether a component belongs in the system
at all, whether a value has earned a semantic name, whether a variant should be
a prop or a composition — these are decisions, and the rule is an argument to
weigh. A repo can pass every check and still be a design system in name only.

## Before you write

1. **Look for the token first.** `dsbridge tokens --grep spacing`. Inventing a
   second name for a value that already has one is how a system splits in two.
2. **Look for the component first.** A raw `<button>` beside a `Button` is a
   second design of the same thing, and it is the one that misses the focus
   ring, the loading state and the tap target.
3. **Know which level you are writing at.** An atom composes nothing, a
   molecule composes atoms, an organism composes molecules. A component that
   reaches upward is a circular dependency waiting for the second consumer.

## After you write

Run `dsbridge check`. Fix by root cause: several findings across files are
usually one missing token or one component doing its own layout. Then read the
diff once more and ask the question no rule can — is this in the system because
two apps need it, or because one app needed it today?
